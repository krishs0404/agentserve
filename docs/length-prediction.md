# Do keyword estimates predict agent output length?

**Recorded trace statistics, not GPU measurements or a scheduling simulation.**

The existing keyword heuristic did slightly worse than a constant training-set
median on held-out sessions. Previous-turn length did worse overall, despite
lower error on the longest outputs. These findings justify testing the prediction
assumption before claiming scheduling gains.

## Data and protocol

The tracked file `notes/lmcache_lmcache_787_pairs.jsonl` contains **24,880 rows
from 767 unique session IDs**, despite its filename. Each row has a truncated
last user/tool message, recorded output token count, session ID, and model name.
There are four models; minimax-m2.5 accounts for 18,540 rows. These are heterogeneous
provider token counts, not outputs generated by AgentServe.

Five seeded 80/20 session splits (11, 22, 33, 44, 55), each with 613 training
and 154 test sessions, keep every turn from a session on one side. The same
held-out turns are scored by all three predictors. No fitting or parameter
selection uses test labels. Predictors are:

- Constant median output length computed on training turns (MAE baseline).
- Existing keyword classifier, unchanged: estimates 20, 100, or 256 tokens.
- Previous observed output in the same session, falling back to the training
  median on the first turn. File order is assumed to preserve within-session order.

Previous-turn evaluation is causal online evaluation: earlier held-out outputs
become visible after completion. It never reads a future output or another session.
No GPU warmup or wall-clock repetitions apply to these deterministic statistics.

## Results

Arithmetic means of the five split metrics, in recorded output tokens (lower is better):

| Predictor | Request MAE | Session macro MAE | Long-output MAE |
|---|---:|---:|---:|
| Training median | 144.49 | 141.09 | 784.17 |
| Keywords | 147.66 | 144.49 | 787.92 |
| Previous turn | 164.43 | 167.14 | 544.99 |

Session macro MAE gives every session equal weight, avoiding domination by long
sessions. Long outputs are those at or above the training split's 90th percentile;
this subset is descriptive and does not define a scheduling policy.

Paired bootstrap resamples test **sessions**, with replacement, 1,000 times per
split. Keyword minus median session MAE is positive on every split: +2.79 to
+4.13 tokens. Every split's conditional 95% percentile interval excludes zero;
for seed 11 the interval is [+1.99, +4.20]. The effect is small. Overlapping test
sets mean the five splits are not independent replications; these intervals do
not cover dataset collection bias or future workload shift.

The previous-turn predictor has lower long-output error, but higher aggregate
error. A single mean hides that tradeoff. MAE also does not establish ranking
quality, short-job identification, scheduler throughput, or fairness. This study
does not prove that priority scheduling helps or hurts completion time.

## Reproducibility

Run `python3 scripts/study_lengths.py` from the repository root. The script uses
the standard library and the existing classifier. Inspect:

- `experiments/length_prediction/summary.json`: input SHA-256, runtime, model
  composition, exact splits, thresholds, per-split metrics, and bootstrap intervals.
- `experiments/length_prediction/predictions.jsonl`: all test predictions and labels
  for each seed, without duplicating prompt text.
- `tests/test_length_study.py`: split disjointness, causal previous-turn features,
  and independence of training thresholds from test labels.

## Limits and next decision

This is a convenience extract, not a new workload dataset. The current public
[dataset card](https://huggingface.co/datasets/DiscoPosse/lmcache-agentic-traces)
describes the upstream fields and timing model. The existing converter names a
different upstream namespace; the local extract has no pinned upstream revision.
Its hash establishes reproducibility of this study, not upstream equivalence.
Related tasks across different session IDs may still share content. No task-family,
chronological, or model-held-out generalization is established.

Prompt truncation removes state that might predict patch generation. Output counts
may reflect provider-specific tokenizers and stopping policies. The study lacks
full tokenized contexts, real tool gaps, cache keys, and hardware service times.
It cannot support prefix hit rates or GPU/session speedup claims.

Workstation inspection found an RTX 5090 (32 GB), driver 580.178.04, with roughly
15.9 GB occupied by other processes. Cached checkpoints were delta_net and huginn,
not Llama. No other process was stopped and no GPU benchmark was run. The Llama
implementation computes ordinary theta-based RoPE and has no scaling field;
pretrained Llama 3.2 parity remains unvalidated. Correctness must precede timing.

A useful follow-up is a dependency-preserving replay with explicit tool waits,
paired workloads, burst/concurrency sweeps, and long-request slowdown. The current
converter's fixed two-second generation estimate must not be treated as measured
service time. [TraceLab](https://arxiv.org/abs/2606.30560) motivates those dimensions;
its results are external context, not evidence about this engine.
